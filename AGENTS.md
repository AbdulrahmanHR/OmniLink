## What is OmniLink?

OmniLink is a cross-platform **desktop application** for configuring, flashing, and monitoring **ExpressLRS** (ELRS) drone radio hardware. It targets FPV drone pilots and RC hobbyists, replacing the existing ExpressLRS Configurator with a modern UI, live telemetry visualization, and an AI-assisted configuration assistant.

The app is built as a **standalone community tool** — it does not depend on any hardware vendor relationship to function.

## Key Architecture Decisions

### Two-Phase Build Strategy

Physical ELRS hardware was unavailable during early development, so the project follows a two-phase approach:

- **Phase 1 (done):** Complete high-fidelity UI driven by mock/simulated data.
- **Phase 2 (in progress):** Each mock is swapped for the real Rust/serial/SQLite backend behind already-isolated seams.

### Tauri IPC Bridge

All Rust ↔ JS communication goes through `src/lib/tauri.ts`. This file contains:
- Typed wrappers around `invoke()` for each Rust command
- Typed event listeners for `device://`, `flash://` event streams
- All DTO interfaces matching the Rust side

**When adding a new Rust command**, always add the typed wrapper + DTO interfaces in `tauri.ts`, then register the handler in `lib.rs`'s `invoke_handler!` macro.

### Tauri Events (not request-response)

Long-running operations (device connection, flashing, telemetry) use Tauri's **event system**, not request-response. The Rust side spawns a worker thread and emits events (`device://connected`, `flash://progress`, etc.). The frontend listens via typed helpers in `tauri.ts`.

## Design System — "Signal Lab"

The visual identity is an oscilloscope/spectrum-analyzer inspired dark-first theme. Three themes exist:

| Theme    | CSS class | Description                                      |
| -------- | --------- | ------------------------------------------------ |
| Dark     | `.dark`   | Primary — oscilloscope green on deep navy        |
| Light    | (`:root`) | Clean lab white, high-contrast                   |
| Carbon   | `.carbon` | PCB-inspired — copper accents on carbon-fiber bg |

Design tokens are defined as CSS custom properties in `src/index.css` using OKLCH colors. The `@theme inline` block bridges them to Tailwind utility classes.

**Key design principles:**
- Fonts: Inter (body), Space Grotesk (headings), IBM Plex Mono (code/telemetry)
- All telemetry status colors (`--status-good/warning/critical`) stay consistent across themes
- `prefers-reduced-motion` is respected — animations become instant
- Minimum window width: 900px (desktop app, not mobile)
- Visible keyboard focus states on every interactive element

## Coding Conventions

### TypeScript

- **Strict mode** is on (`strict: true`, `noUnusedLocals`, `noUnusedParameters`)
- Path alias: `@/` maps to `./src/` (configured in both `tsconfig.json` and `vite.config.ts`)
- Pages are **lazy-loaded** via `React.lazy()` in `App.tsx`
- ESLint: `typescript-eslint` recommended + `react-hooks` + `react-refresh` rules
- Unused vars prefixed with `_` are allowed (`argsIgnorePattern: "^_"`)

### Internationalization

- **Zero hardcoded user-facing strings.** Every visible string must go through `react-i18next` (`useTranslation` hook or `t()` function).
- Translation files live in `src/locales/en/translation.json`
- Number/date formatting uses the JavaScript `Intl` API

### State Management (Zustand)

- Each domain has its own store file in `src/stores/`
- Stores are re-exported from `src/stores/index.ts`
- The stores follow a flat, action-based pattern (no reducers)

### Component Organization

- `src/components/ui/` — Generic shadcn-style primitives (Button, Card, Dialog, Sheet, etc.)
- `src/components/<domain>/` — Feature-specific components (telemetry, wizard, ai, etc.)
- `src/pages/` — One file per route, exported as named exports

### Rust Backend

- Commands live in `src-tauri/src/commands/` (one file per domain)
- The CRSF parser is in `src-tauri/src/crsf/mod.rs` (~25KB, full protocol implementation)
- Long-running work spawns `std::thread` (not async) and emits Tauri events
- Managed state uses Tauri's `.manage()` pattern (e.g., `DeviceManager`, `FlashManager`)
- Serial port I/O uses the `serialport` crate directly (not `tauri-plugin-serialport`)
- API keys are stored backend-side with `0600` permissions, never returned to the frontend (only boolean `ai_has_api_key`)

## Development Commands

All commands run from `projectomni/`:

```bash
# Frontend dev server (browser, fastest for UI work)
npm run dev

# Full native desktop app
npm run tauri dev

# Quality gates (all must pass for CI)
npm run typecheck     # tsc --noEmit
npm run lint          # ESLint over src/
npm test              # Vitest unit tests
npm run build         # Full production build (tsc && vite build)
```

**Rebuild `src-tauri` before verifying any Rust-side change.** `npm run dev`
reloads the frontend; nothing reloads the Rust half. Running a prebuilt
`src-tauri/target/debug/omnilink` against a `npm run dev` server puts current JS
over whatever Rust last compiled — and a stale backend presents as a *product*
defect (a command answering "Unavailable", a control that never renders), not as a
build error, so it gets written up as a bug. This cost a `3.0.3` verification pass
its entire run against a `target/debug` eleven hours older than the commits under
test. `npm run tauri dev` compiles Rust first; `cargo build --manifest-path
src-tauri/Cargo.toml` does it without opening a window. Full note:
[`CONTRIBUTING.md`](CONTRIBUTING.md#the-rust-half-does-not-rebuild-itself).

## Testing

- **Test runner:** Vitest 3 (unit), configured in `vitest.config.ts`; Playwright (E2E, M20) in `playwright.config.ts`
- **Test location:** `tests/unit/*.test.ts` (vitest); `tests/e2e/*.spec.ts` (Playwright). `vitest.config.ts` **excludes** `tests/e2e/**` so the two runners stay separate.
- **Environment:** unit tests run in Node (not jsdom — pure logic); E2E runs the real app in headless chromium (`npm run e2e`, after `npm run build` or against `npm run dev`).
- **E2E (M20):** five flow specs (logs/simulator/map/wifi/backpack) + an offline-degradation spec. `tests/e2e/_helpers.ts` installs a Tauri-v2 IPC+event **mock seam** (`installTauriMock`/`emitTauri`) so store-driven flows (WiFi discovery, Backpack) run headlessly through the genuine seam; logs/simulator drive real pure-browser CSV import. `@axe-core/playwright` asserts zero serious/critical a11y violations per new page.
- **Existing test suites:** telemetryCrsf, telemetryBatch, wizard, wizardFlash, profileDiff, aiContext (+ M11–M19 suites)
- **Path alias:** `@/` works in tests (mirrored in vitest config)
- **CI:** GitHub Actions runs lint (ESLint), typecheck (`tsc --noEmit`), unit tests, Rust fmt/clippy/test (job `lint-and-test`), and a separate `e2e` job (Playwright headless).
- **Commands:** `npm test` (vitest), `npm run e2e` (Playwright).

## Important Project Policies

1. **BYOK AI only — permanently. This is project policy, not a phase.** No payments, no accounts, no managed credits, no LemonSqueezy, no hosted answer path — not in `3.x`, not later, not behind a flag. It was originally written as a *v1.0 scope boundary* with the paid Managed tier planned for v2; **that plan is dead.** v3.0 (M69, decision **D35**) retired the v2.1 accounts/billing line and the v2.3 / v2.4-Managed platform stack — **retired, not deferred** — and deleted the code that mocked them at HEAD. There is no later version in which this becomes payments. `3.0.x` and beyond must not reintroduce accounts, billing, entitlements, a server, or any hosted surface; see policy §8. The BYOK path (`commands/ai.rs`, `LlmAdapter`, OS-keychain key storage) is **real and stays** — the user brings their own key, runs Ollama locally, or uses no AI at all. If a request implies "when we add the paid tier," the answer is that there is no paid tier and no plan for one; the only door left open is written down in `../docs/plans/v3.0_MILESTONES.md` §11 (decision **D40**), and it is narrow, explicit, and inert.
2. **AI safety:** The AI assistant never receives binding phrases, GPS coordinates, MAC addresses, IP addresses, or emails. Context is sanitized in `commands/ai.rs` via `sanitize_context()`. The AI cannot suggest changes to safety-critical defines (failsafe, arming).
3. **Flash safety:** A TX target cannot be flashed onto an RX device, and vice versa. Config is backed up before every flash.
4. **Offline-first:** Core workflows (device config, flash from cache, telemetry, profiles) function with zero network connectivity.
5. **Changelog notification:** The changelog must be updated and notified immediately after each version bump.
6. **Sub-branch naming:** Sub-branches cut for milestone implementation must be named directly according to the 3-number version being implemented (e.g., when implementing M21 and M22, the sub-branch must be called `1.6.0`, and so on).
7. **Build-workflow triggers:** The installer build workflows (`.github/workflows/*-build.yml`) trigger only on the long-lived **main branches** — `main` and the current integration branch (`v3` as of v3.0.0) — never on an in-progress sub-branch (e.g. `3.0.0`). A sub-branch's installers get built when it is merged back into its integration branch, which is already a trigger. `ci.yml` additionally runs on `pull_request` to those same branches (restored at M68); `release.yml` is tag-triggered and independent of all of this.
8. **No recurring cost, no server, no accounts.** *(Added at v3.0.0 — M70, from `../docs/plans/v3.0_MILESTONES.md` §4.)* OmniLink is a desktop application that must cost its author **nothing** to operate, permanently. Three parts, all hard:
   - **No recurring cost.** No hosting, no managed database, no auth vendor, no per-MAU or per-seat service, no paid CI tier, no paid domain requirement, no telemetry or analytics vendor. Any deliverable that would create a monthly bill is **out of scope by definition and is rejected rather than negotiated** — this is the v3 line's defining constraint, not a preference. A paid code-signing certificate is the one live question in this category and must clear the rule explicitly before it is bought.
   - **No server.** There is no backend and there will not be one. Where a feature seems to need one, the answer is to find the version of it that does not: **M71 replaces cloud profile sync with a folder the user already owns** (decision **D37**) — `.elrsp` files written to a user-picked directory, which gets multi-device sync for free if that directory happens to live in Dropbox, Drive, OneDrive, Syncthing or a git checkout. That is the pattern to reach for.
   - **No accounts, ever.** No login, no identity, no session, no user record — **local or remote**. A local "account" is still an account and is still refused.

   Also non-negotiable under this policy: **offline-first is preserved** (no core workflow may require a network), the `sanitize_context()` privacy baseline may not be weakened, and **no telemetry or analytics call of any kind** may be added. Funding is passive donation links only (decision **D38**) — nothing in the app processes money, stores an identity, or calls an API; donations buy no capability, no priority and no badge.
